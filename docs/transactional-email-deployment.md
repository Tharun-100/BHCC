# Transactional email deployment

BHCC sends transactional email from Django through Anymail and Resend. Incoming mail for the support address is configured separately through the domain's email-routing provider.

## Resend setup

1. Add and verify `bhaktivedantahealthcare.tech` in Resend.
2. Add the exact SPF and DKIM records generated by Resend to the authoritative DNS provider.
3. Wait until Resend reports both SPF and DKIM as verified.
4. Create a production API key with sending-only access, restricted to the verified domain when available.
5. Do not commit or expose the API key to the frontend.

## Coolify variables

Configure these as runtime variables for the Compose resource:

```env
EMAIL_BACKEND_MODE=resend
RESEND_API_KEY=re_replace_with_the_production_key
DEFAULT_FROM_EMAIL=Bhaktivedanta Healthcare <noreply@bhaktivedantahealthcare.tech>
SUPPORT_EMAIL=support@bhaktivedantahealthcare.tech
FRONTEND_URL=https://bhaktivedantahealthcare.tech
ADMIN_NOTIFICATION_EMAIL=replace_with_the_admin_inbox
CLINIC_TO_EMAIL=bhaktivedantahealthcarecentre@gmail.com
CLINIC_LOCATION=Bhaktivedanta Healthcare Centre, Newtown, Kolkata
```

Keep all private email variables unavailable at build time. Lock `RESEND_API_KEY` after saving it. The application deliberately fails to start in Resend mode when the API key, sender, support address, frontend URL, or administrator notification address is missing.

Redeploy the Compose resource. The backend container automatically runs database migrations before Gunicorn starts.

## Acceptance checks

1. Request a staff login OTP and confirm the text and HTML message arrives.
2. Submit the contact form and confirm the clinic receives it with the visitor in Reply-To.
3. Complete a pay-at-counter booking and confirm exactly one appointment message arrives.
4. Complete a Razorpay test payment and confirm exactly one appointment message arrives after verification.
5. Confirm appointment messages contain no diagnosis, clinical notes, passwords, or payment credentials.
6. Review the Resend delivery log for rejected or bounced messages.
7. Register a new patient, verify that no login is possible before verification, and open the verification link.
8. Request two verification emails within 60 seconds and confirm only one is sent.
9. Request a password reset for both a known and unknown address and confirm the API response is identical; repeat within 60 seconds and confirm no duplicate message is sent.
10. Reset the password, confirm the link cannot be reused, and confirm the security-alert email arrives.
11. Create a doctor/staff account and confirm the configured administrator receives a notification without a password.

For local development, set `EMAIL_BACKEND_MODE=console`; messages are printed by Django and are not sent externally.

Run backend email tests without requiring PostgreSQL database-creation privileges:

```powershell
$env:DJANGO_TEST_SQLITE="true"
python manage.py test api
```

Cloudflare Email Routing or another incoming-mail provider must separately forward `support@bhaktivedantahealthcare.tech` to a monitored clinic inbox.
